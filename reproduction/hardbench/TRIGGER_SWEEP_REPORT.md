# 单点候选穷举（single_candidate_sweep_v1）

日期：2026-09-20

## 结论先行

本轮在 3 道代表题上穷举了 N 轨迹的全部 47 个 inference 候选点，每条反事实
轨迹只调用一次 memory。位置明显影响输出，但**没有一个单点注入把原本错误的题
救对**：评分得到的 7 个正确变体全部来自本来就正确的 `gsm8k_test_0710`。

因此，现有数据支持“Trigger 时机有因果作用”，但不支持“只要学会挑位置，当前
Weaver 就能修复这些错误”。对两道 N 失败题，当前候选集合中不存在 exact-positive
训练样本。

## 固定设计

选择三个作用互补的案例：

- `gsm8k_test_0710`：N 正确，但 always-invoke 把答案破坏为 44.1。
- `gsm8k_test_0611`：人工点位让数值明显靠近 gold，但仍未答对。
- `gsm8k_test_0754`：人工点位让数值远离 gold。

候选数直接取自已经封存的 N 原始轨迹，分别为 7、36、4。对候选 `k` 的运行在
前 `k-1` 个候选全部跳过，仅在 `k` 注入一次；因为 greedy 解码在注入前与 N
同轨，所以每个计划候选都能精确复现。事件审计结果为：47 条、零缺失、零重复、
47/47 `intervention_reached=true`、47/47 inference augmentation count 为 1。

| sample | N 结果 | 候选数 | 输出改变 | exact-positive | 唯一预测数 | 数值距离：改善 / 持平 / 恶化 | 最佳点 |
|---|---:|---:|---:|---:|---:|---:|---|
| `0710` | 45 ✓ | 7 | 2/7 | 7/7 | 1 | 0 / 7 / 0 | 全部，误差 0 |
| `0611` | 6,003,125 | 36 | 33/36 | 0/36 | 15 | 23 / 4 / 9 | #1 → 1,625,000；误差 175,000 |

24 个改善、11 个恶化、12 个持平。这个统计只能说明扰动方向，不能替代 exact
correctness 或推理正确性。

## 逐题解释

### `gsm8k_test_0710`：问题是重复注入，不是某一个坏点

7 个单点变体的最终答案全部为 45。候选 #4 和 #6 改变了推理文本，但仍得到正确
答案；其余 5 个 completion 与 N 相同。相比之下，官方 always 条件在前三个候选
连续注入后得到 44.1。

这说明该题的破坏来自多次 memory 的组合／剂量效应，而不是任何一个单点本身。
将 Trigger 当成各候选独立的二分类器会遗漏这种历史依赖；策略至少应看到已经
调用过多少次、前一次 memory 内容以及当前推理状态。

### `gsm8k_test_0611`：位置效应很强，但没有真正修复

36 个点产生 15 种最终预测，33 个 completion 改变。候选 #1 的数值误差最小，
也就是上轮人工选择的位置；早期 #2–#14 大多比 N 更接近，#15 之后则在改善、
持平和恶化间跳变。

然而 #1 不是语义上的正确修复。它仍把“首 5 个月总 funding 为 100,000”误读成
“每月 100,000”，随后又写出 `750,000 × 5 = 375,000`，靠抵消性算错得到
1,625,000，恰好接近 gold 1,450,000。真正解法应先得到首段每月 20,000，随后
45 个月每月 30,000，再加初始 100,000。

因此不能用“到 gold 的数值距离”直接监督 Trigger，否则 #1 会被错误标成强正例。
本题的 36 个候选里没有一个 exact-positive，当前 Weaver 没有提供可供 Trigger
挑选的正确分支。

### `gsm8k_test_0754`：较晚点更接近，但首个换算错误未修复

人工点 #1 与 #2 都得到 40，误差从 N 的 22 扩大到 49；#3 得到 107，误差缩小
到 18；#4 与 N 相同，仍为 67。#3 位于第一段 sticker 交易之后、第二段交易开始
时，是这题最好的单点，但模型已经把 27 枚 small stickers 直接当作 27 枚 large
buttons，而正确换算应为 `27 / 3 = 9`。后续 memory 只能重排错误中间量，没有
恢复正确答案 89。

## 对 Trigger 训练的含义

1. **先验证可救性，再训练触发器。** 如果某题的所有单点都没有 exact-positive，
   Trigger 无法仅靠选时机解决它；应先改 Weaver 或候选生成。
2. **标签必须验证语义。** 数值距离会把抵消性错误当成改善，至少需要 exact
   verifier，并最好检查关键中间关系。
3. **Trigger 应是有状态的预算策略。** `0710` 表明单点全安全、连续三次却有害；
   独立 Bernoulli／逐点二分类不足以表达剂量和历史交互。
4. **候选生成仍是瓶颈。** 当前候选有不少落在金额逗号、小数内部，而不是自然
   推理边界；先提高候选语义质量会让 Trigger 的学习目标更干净。

最小的下一步是只在 `0710` 上补前三个候选的两两组合和三点组合，共 4 条轨迹，
定位 repeated-injection 的最小破坏集合。对 `0611` 与 `0754` 则不应继续训练
位置分类器，而应先测试更好的 Weaver memory 或取消 prompt augmentation。
